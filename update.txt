Ano, přesně tak.

Ten layer není součástí Real-Time Edge manifestu, takže pokud jsi postupoval podle předchozího návodu, adresář ../recipes-cachepartition zatím neexistuje.

Nejdříve si ověř obsah workspace:

find . -maxdepth 2 -type d | grep cache


Pokud nic nenajdeš, naklonuj repository:

cd ~/yocto-real-time-edge

git clone -b lf-6.12.20-2.0.0 \
https://github.com/nxp-imx-support/recipes-cachepartition.git


Pak zkontroluj:

ls recipes-cachepartition


Měl bys vidět něco jako:

imx-atf
linux-imx
usecache
README.md


Potom přidej layer:

cd build-imx95

bitbake-layers add-layer ../recipes-cachepartition


Pokud dostaneš:

Specified layer directory does not contain a conf/layer.conf file


tak je zde další problém:

recipes-cachepartition totiž není klasický Yocto meta-layer. Podle obsahu repozitáře jde spíše o kolekci patchů a receptů pro AN14474 než o plnohodnotný layer. Webová dokumentace NXP uvádí pouze, že repozitář obsahuje implementaci cache partitioningu pro Linux a ATF, nikoliv že jej lze přímo přidat přes bitbake-layers add-layer.

V tom případě bych potřeboval vidět obsah:

tree -L 2 recipes-cachepartition


nebo

find recipes-cachepartition -maxdepth 2 -type f


Protože je dost možné, že pro Real-Time Edge bude potřeba:

vytvořit vlastní meta-cachepartition,
převzít .bbappend soubory z repozitáře,
nebo aplikovat patch přímo do linux-imx a imx-atf.

Tohle je mimochodem přesně ten bod, kde AN14474 bývá nejasná. Nejdřív bych ověřil strukturu repozitáře a podle toho navrhl správnou integraci do nxp-image-real-time-edge.
